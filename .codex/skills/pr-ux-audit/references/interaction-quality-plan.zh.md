## 1. 背景与预期结果

上一版本进行了较大范围的 UI 和页面布局调整，后续出现较多屏幕适配、字段展示、组件适配、图标及文案一致性、中英文展示问题。设计师需要在本地构建后逐项发现并补齐，造成重复沟通和返工。

本工作的结果应同时包括：修复实际体验缺陷、建立可复用的验收规则、让开发交付包含真实操作验证，减少下一轮由设计师兜底发现基础问题的工作。文档完成或工具接入不代表产品体验已改善。

## 3. 范围与执行顺序

1. 建立上一版本改动页面清单，标记布局变化和共享组件影响范围。
2. 优先走查布局变化最大的页面组，包含列表、详情、表单、弹窗等实际存在的类型。
3. 从中选择一条高频完整任务验证页面间衔接；具体页面及任务待确认。
4. 修复时优先排查共享布局、组件、图标和语言资源的共性原因，避免在多个页面分别打补丁。
5. 在其他使用同一组件的页面复测，通过后逐步扩大范围。

没有具体版本、运行环境、页面截图或复现记录前，不将用户描述扩写成已确认缺陷。已有验证结果见文首执行记录。

## 4. 执行前确定验证范围

每次走查记录产品版本或提交、运行地址、浏览器版本、语言、视口尺寸、缩放、角色和测试数据。以下为候选范围，需结合产品支持范围确认，不直接承诺全端适配。

| 维度 | 建议样本 | 验证重点 |
| --- | --- | --- |
| 桌面宽度 | 1440×900、1280×800、1024×768 CSS 像素 | 分栏、表格、弹窗、操作区的挤压和滚动 |
| 连续缩放窗口 | 从常用宽度缩至已约定最小宽度 | 临界宽度错位、跳变、覆盖 |
| 页面缩放 | 100%、200% | 内容重排、操作可达、文字可读 |
| 语言 | 中文、英文；若产品支持则切换验证 | 翻译完整性、文字长度、状态及提示同步 |
| 内容 | 空、正常、长中文、长英文、无空格字符串、多条记录 | 截断、换行、空值、滚动 |
| 运行状态 | 正常、加载、失败、重试、无权限（适用时） | 反馈、输入保留、恢复路径 |

移动端是否支持、最小视口、支持浏览器、主题和角色范围待确认。先在全部目标页面验证两种语言的正常状态；对高风险页面叠加最窄视口、长内容和异常状态。共用布局变更后应扩大相关组合的覆盖。

## 5. 可执行走查清单

每条规则记录为“通过 / 失败 / 不适用 / 未验证”；不适用说明原因，未验证写明缺少条件。每次任务选取相关规则，无需机械执行所有条目。

| 编号 | 检查对象 | 操作与通过条件 |
| --- | --- | --- |
| L01 | 页面布局 | 在目标尺寸及连续缩小窗口时，导航、正文、操作区无重叠、遮挡或非预期横向溢出 |
| L02 | 主次与对齐 | 对照已确认设计基线，标题、字段、操作区对齐和层级一致；主操作位置可辨认 |
| L03 | 页面滚动 | 长页面可到达底部；固定头尾不遮挡内容和按钮；嵌套滚动行为清楚 |
| L04 | 弹窗与抽屉 | 窄屏、短屏、长内容下标题、关闭及提交操作可达；滚动区域合理 |
| L05 | 表格与列表 | 长字段不挤掉关键操作；需要横向滚动时范围明确，分页和关键内容可达 |
| L06 | 浮层 | 打开菜单、下拉、Tooltip 后，内容不被容器裁切，不越出可用范围导致无法操作 |
| I01 | 图标 | 同一动作使用同一语义及约定图标；尺寸、线条风格、颜色和对齐遵守基线 |
| I02 | 图标操作 | 只有图标的按钮可理解，有可访问名称；适用时提供悬停或焦点提示 |
| T01 | 名称与术语 | 同一对象在导航、标题、表单、列表、弹窗及提示中名称一致；差异有明确语境 |
| T02 | 操作文案 | 按钮文案说明实际动作；入口名称、目标标题和确认文案含义对应 |
| T03 | 文本格式 | 标点、大小写、单位、日期时间及状态名称遵守已确认规则 |
| T04 | 按钮长度与含义 | 普通操作按钮用简短动作及必需对象，不塞入整句说明；保留发布、退出、重启等重要后果，切换与进行中状态含义准确；实际中英文在目标宽度下不挤压、重叠或截掉关键语义，长文案移到邻近说明；字数仅初筛，选择卡片和必要复合动作按语境判断（TXT-04） |
| Z01 | 翻译覆盖 | 两种语言下检查标题、标签、占位、校验、空态、提示、浮层；无遗漏翻译键或非预期混用 |
| Z02 | 长度适配 | 切换英文及填入长内容后，按钮、标签、表头和弹窗不遮挡或丢失关键含义 |
| Z03 | 字段值 | 枚举及系统状态按约定本地化；用户输入、标识符、路径等保留原值，不机械翻译 |
| Z04 | 语言切换 | 若支持运行时切换，新打开浮层及新触发反馈使用当前语言；编辑数据不意外丢失 |
| F01 | 字段结构 | 标签、必填、默认值、说明、单位、只读及禁用状态表达清楚且同类一致 |
| F02 | 输入校验 | 验证空值、边界和非法输入；错误定位到相关字段，说明纠正方法，正确内容保留 |
| F03 | 输入与键盘 | Tab 顺序合理且焦点可见；Enter、Esc 按组件语义工作，中文输入法确认不误提交 |
| F04 | 截断与空值 | 缺省值不冒充真实值；长文本按用途换行或截断，关键完整内容可查看或复制 |
| C01 | 组件状态 | 按钮、输入、选择器等适用状态有区分；交互和样式遵守同类组件基线。命令按钮优先用 Button / IconButton，按钮式导航用 LinkButton；核对封装来源和实际语义，记录原生控件、自定义卡片及选择项的合理例外，不把原生标签一律视为缺陷 |
| C02 | 跨页复用 | 同类组件在不同页面的交互、间距、尺寸及反馈一致；业务差异有依据 |
| S01 | 初始与空态 | 区分首次使用、无记录、无搜索结果及加载失败，说明下一步可做什么 |
| S02 | 加载与提交 | 操作有可见反馈，防止重复提交；失败后控件恢复可操作，不永久停在加载状态 |
| S03 | 失败与恢复 | 模拟请求失败或超时，提示可理解、输入保留；适用时可重试并完成任务 |
| S04 | 成功反馈 | 成功结果可见，列表或详情更新符合预期，下一步入口清楚 |
| P01 | 完整任务 | 从入口完成目标，返回及取消位置符合预期，无死路或意外跳转 |
| P02 | 中断与防错 | 未保存离开、刷新、取消及危险操作按已确认规则处理，说明保留、丢弃或恢复结果 |
| P03 | 角色权限 | 适用时验证不同角色入口及拒绝反馈，不出现可点击却无解释的操作 |

## 6. 协作与交付流程

| 阶段 | 设计师 | 开发 / AI | 必须留下的结果 |
| --- | --- | --- | --- |
| 开发前 | 确认目标、设计基线、术语和适用规则 | 列出受影响页面、组件和验证范围，补齐遗漏状态 | 本次验收条件 |
| 开发中 | 决策涉及业务含义和体验取舍的问题 | 复用既有组件，定位共性原因并修复 | 问题与修复记录 |
| 开发自查 | 无需重复执行开发基础自查 | 在真实页面完成相关矩阵及规则验证，提供证据 | 逐项结果和未验证项 |
| 设计验收 | 检查核心任务、感知质量和争议点 | 协助复现、修复并复测 | 接受或退回的具体原因 |
| 回归 | 确认代表性基线 | 执行相关页面回归，沉淀稳定检查 | 回归结果和遗留事项 |

AI 自查指令模板：

> 先列出本次 UI 改动影响的页面、共享组件和语言资源，并依据本方案选择相关检查编号。启动真实产品，按约定语言、视口、数据和状态实际操作。发现问题时记录复现、预期、实际、影响和截图；修复后在原场景及共享组件使用处复测。涉及业务取舍或缺少设计基线的地方列为待决策。结果逐项标记通过、失败、不适用、未验证，不能凭代码推断页面已通过，也不能为通过测试随意修改验收条件或截图基线。

## 8. 工具与回归落地原则

- 先复用项目现有验证方式；具体测试技术和接入成本在试点中评估。
- 静态检查适合发现部分缺失语言资源和约定违规，不能证明实际展示正确。
- 浏览器自动化适合稳定的表单、语言切换、重复提交和流程验证。
- 截图比较适合发现布局及视觉回退，基线必须人工确认，不能以批量接受截图替代验收。
- 组件示例适合集中覆盖状态和长内容；是否引入 Storybook 由重复问题和维护成本决定。
- 信息架构、术语含义及流程是否符合用户预期由人工确认。
- 修改前端代码、配置或测试时，须先遵守 `docs/tech/web/development.md`。本稿不改变现有开发规范。
