# 交互设计规范

适用于 `web/app` 中影响布局、控件、导航、字段、图标、文案、多语言及交互状态的改动。[英文版](interaction-design.md)为 AI 规范主文档，两版规则编号对应。

[前端开发规范](development.md)管理代码结构、样式、国际化机制及测试命令；[组件规范](ui-components.md)管理组件 API、键盘行为与浮层。本文规定用户可感知的交互结果。[走查方案](../../ux/interaction-quality-plan.zh.md)管理推广、问题记录和效果评估。

## 开发前

- 明确受影响页面、共享组件、语言和用户任务，选择适用规则。
- 复用已认可设计、组件契约和术语，不把已知缺陷当作惯例。
- 共性问题优先修复共享原因并复测使用处，避免扩大到无关页面重设计。
- 沿用约定的浏览器、视口和角色范围；尚无约定时记录实际验证范围及待明确限制，不自行承诺移动端支持或最小宽度。

## 布局与内容

- **LAY-01：** 支持尺寸下，导航、内容及操作可读可达，无重叠和非预期整页横向滚动；宽表格可在明确的容器内滚动。
- **LAY-02：** 长文本、无空格标识符、空值和大量记录不能挤掉关键操作。按用途换行或截断，关键完整值可查看；不靠缩小字体或隐藏必要内容解决适配。
- **LAY-03：** 短屏和窄屏下弹窗、抽屉的标题、关闭及完成操作可达；固定区域不遮挡内容，滚动区域清楚。
- **LAY-04：** 菜单、选择器、气泡和提示在视口边缘、滚动容器和弹窗内仍可操作；复用组件碰撞检测及层级，不随意抬高 z-index。
- **LAY-05：** 使用既有布局组件和 token，保持已认可的对齐、信息层级及主操作位置。

## 图标、文案与多语言

- **TXT-01：** 同一操作或对象在导航、标题、字段、弹窗和反馈中使用统一图标及术语；有意的语境差异在改动中说明。
- **TXT-02：** 操作名称对应真实结果，入口与目标标题语义一致。纯图标控件有本地化可访问名称；含义不清时提供悬停及焦点可用的可见提示。
- **TXT-03：** 沿用标点、大小写、单位和日期时间格式；已有产品或业务术语时不另创译法。
- **TXT-04：** 按钮文案简短易懂，说明动作及当前语境必需的对象；普通操作按钮不承载冗长解释或前置条件，说明移到邻近辅助文案。保留发布、退出登录、重启等重要后果，区分切换及进行中状态。用实际中英文和相关状态检查可用空间，不挤压相邻操作、不重叠、不因截断丢失关键含义；不靠缩小字号或换成难懂的纯图标解决过长问题。字数和词数仅供初筛，不是统一硬上限；产品名、必要的复合动作及含说明的选择卡片需结合语境判断。
- **LOC-01：** 已翻译路径改动时同步全部支持的语言资源，覆盖占位、校验、空态、提示、菜单及异步反馈，不露出翻译键或非预期混合语言。
- **LOC-02：** 产品支持中英文时用真实中英文和长标签验证。切换语言后，新打开的浮层和反馈使用当前语言，不丢失编辑内容。
- **LOC-03：** 系统标签和枚举状态通过既有映射翻译，保留用户内容、ID、路径及协议值；例如翻译状态的显示名称，不修改 API 状态值。

## 字段、控件与键盘

- **FORM-01：** 字段有持续可见且关联的标签，区分必填、选填、只读及禁用；解释有业务意义的默认值和单位，不以占位文字代替标签。
- **FORM-02：** 验证相关空值、边界及非法输入，错误与字段关联并说明纠正方法；失败保留有效输入，不为恢复编辑而持久化秘密信息。
- **FORM-03：** Tab 顺序合理、焦点可见，保留共享组件的 Enter/Esc 及焦点恢复行为；输入法确认不误提交或误选择，多行输入不意外由 Enter 提交。
- **FORM-04：** 区分适用的焦点、悬停、选中、禁用、错误和加载态；必要信息不只靠颜色表达，页面不重建基础控件交互。

## 反馈与任务连续性

- **FLOW-01：** 区分初始无数据、搜索无结果、加载、数据不可用及失败；存在下一步时提供入口，不把请求失败展示成正常空态。
- **FLOW-02：** 异步修改有进行中反馈、防重复提交，完成或失败后恢复可操作；成功结果在相关视图体现，不强制每次使用 Toast 或弹窗。
- **FLOW-03：** 失败时尽可能说明恢复方法，保留适当编辑内容，支持重试时提供重试。操作结果不确定时先核实状态，避免引导重复修改。
- **FLOW-04：** 验证入口、完成、取消及返回路径，路由视图还需验证浏览器前进后退。未保存编辑及危险操作遵守约定，按风险提供确认或撤销；不自行新增自动保存、持久化或取消能力。
- **FLOW-05：** 有角色限制时，不可用操作及权限反馈一致，不出现无解释的无响应控件。

## 验证与交付

- 按前端开发规范运行相关检查，使用现有工具为行为改动补充有价值的回归验证；纯文档修改无需前端运行测试。
- 布局及交互改动在真实浏览器验证受影响任务、适用状态、支持语言、长内容及空值、相关视口边界。共享组件可用既有 UI Lab 验证独立状态，并按需检查页面集成。
- 布局改动检查中间窗口宽度及相关缩放行为；走查方案中的建议尺寸是样本，不是新增产品支持承诺。
- 按规则编号记录版本、浏览器、语言、视口及缩放，结果为“通过 / 失败 / 不适用 / 未验证”；说明排除项及阻碍，编译或阅读代码不能代替浏览器验证。
- 可见缺陷提供复现和修改前后证据，修复后复测原场景及受影响共享使用处；不为消除失败而直接接受新截图基线。
- 小改动简短交付，只提供适用证据。缺少设计决策时明确列出，继续独立可验证的工作；尚未设计验收时不宣称已验收。
