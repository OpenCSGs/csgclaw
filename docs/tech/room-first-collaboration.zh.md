# CSGClaw 团队协作模式与执行流程

## 1. 新建入口

私聊由选中的智能体直接处理。新建团队房间时，可先建空房间，也可带首条消息创建。历史「自由发言」群仍可打开。

| 团队模式 | 适用场景 | 房间类型 |
| --- | --- | --- |
| **主持模式**（默认，原「按需协作」） | 目标明确，由 Manager 分工、验收和汇总 | `on_demand` |
| **圆桌模式**（实验性功能，原「自主协作」） | 开放探索，成员按专长参与讨论、主动分工 | `autonomous` |

## 2. 主持模式

- **派工。** 用户需求先到 Manager，直接 @ Worker 也一样。简单问题可直接答复，需要交付时，Manager 拆分任务、指定负责人并派工。
- **并行与依赖。** 同房间的独立目标可以同时推进，同一 Worker 也可在不同任务会话里并行工作。例如开发棋盘时可同时写使用说明，依赖棋盘的测试则要等开发成果通过验收。
- **反馈与结项。** Worker 提交成果后由 Manager 验收。执行失败或确认被手动停止时，系统把原因送回 Manager。Manager 保留已有成果，在原计划上改派或补充工作，最后按目标汇总。用户停止整个目标时，Manager 等该目标正在执行的工作结束后再汇报。

## 3. 圆桌模式

成员开工前在群里说明分工，看到重叠就协调调整。公开消息可以提醒未被 @ 的成员。忙时集中读未读，只能等待同伴交付时就结束本轮，由后续消息重新唤起。分工、阻塞和成果都发回原房间或话题。

用户停止某个成员时，房间暂停后续唤起，其他已开始的回合可以完成。用户再次发言后恢复。

## 4. 团队规则与上下文

房间保存建房时的团队规则。成员共享工作目录，各用自己的模型、工具和权限。主持模式下，Manager 按房间协调，Worker 按子任务延续会话。圆桌模式下，主对话和各话题分别记录未读，发言和回复绑定当前会话。

## 5. 聊天与活动记录

聊天区展示公开回复、附件、问题和审批。输入框上方显示活跃成员，可查看或停止具体执行。右侧活动记录可按成员、状态筛选，查看每轮的触发消息、工具调用和结果。主持模式还可在任务面板查看分工与验收进度。
