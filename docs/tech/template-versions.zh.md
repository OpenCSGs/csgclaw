# 本地模板唯一 ID 与版本管理

从智能体首次保存本地模板时，生成持久化 UUID（`template_uid`）及 V1。此后同一智能体每次保存均在关联模板上生成新版本，内容未变化也递增。原有 `local.<id>` 引用继续兼容，UUID 不随名称、版本或发布地址变化。

不依赖 Git。每个版本包含完整快照、时间、选填提交说明；仅在保存时已登录的情况下记录作者，历史记录不回填。只保留最近 10 个版本的内容和记录，清理后版本号继续递增。回滚不生成新版本，只切换当前生效版本，不删除历史，不修改智能体及其关联。例如 V3 回滚到 V1 后仍保留 V2、V3，下次保存生成 V4，社区发布使用当前生效的 V1。

存量模板不自动关联智能体。首次保存与已有本地引用冲突时，保留该模板唯一 ID，将原内容纳入历史，再保存智能体的新版本并建立关联。后续保存依据持久化关联定位模板，名称变化不产生新的模板身份。

当前生效内容位于 `templates/<id>/`，`.versions.json` 保存关联、提交记录及云端发布信息，`.versions/<revision>/` 保存保留版本快照。历史内部文件不会出现在当前工作区列表，也不会打包上传。

## 社区发布

支持单独保存、单独发布及“保存到本地并发布到社区”。组合操作先保存本地，再上传当前生效快照；直接通过 API 将智能体发布到 official 也先保存本地。发布失败不撤销本地保存。

发布前查询当前登录用户命名空间下的目标仓库。仓库不存在时先创建空仓库，再通过预上传和一次批量 commit 上传过滤后的模板快照，不再上传 ZIP。已存在的仓库直接在默认分支更新：根据预上传返回的 oid 判断 create/update，将本地已移除的文件作为 delete 一并提交；本地未包含的仓库 Git 策略文件（`.gitattributes`、`.gitignore`）保留。本地重命名后复用已关联的云端路径。查询失败时停止发布；提交失败保留本地版本及已有远端仓库。文件内容及预上传 sample 使用 Base64。遇到 LFS 或被忽略的文件会明确报错，避免发布不完整快照。

上传的 `agent.toml` 携带稳定 UUID 与本地版本号。成功后在本地记录站点、命名空间、云端路径、发布版本和时间。本地历史及智能体关联不上传，不需要用户安装 Git。

模板详情会查询已关联的社区模板并显示其版本。模板 UUID 与版本号均一致时显示“当前版本已发布”；版本号不同（包括本地回滚）时显示“与社区版本不同”。无法确认远端版本时，将本地记录明确标注为“上次发布 Vn”，不当作社区当前版本。发布记录按当前站点及账号匹配；旧模板仅存在同名仓库时显示“社区版本待确认”。发布按钮明确显示当前生效的本地版本。

## API

- 保存智能体的 `POST /api/v1/hub/templates` 支持选填 `commit_message`。发布已有模板时可传 `expected_revision`，对应弹窗中展示的版本；若当前生效版本已变化，返回 HTTP 409 和 `template_version_changed`，不会执行上传或删除云端资源。
- `GET /api/v1/hub/templates/{id}/versions`：按版本号升序返回保留记录。
- `GET /api/v1/hub/templates/{id}/versions/{revision}?path=...`：查看历史目录；增加 `file=true` 读取文件。
- `POST /api/v1/hub/templates/{id}/versions/{revision}/restore`：请求体为 `{ "commit_message": "选填" }`，返回当前生效模板，不生成版本。

模板响应增加 `uid`、当前生效 `revision`、最大已分配版本号 `latest_revision` 和可选的 `publications`。CLI 可使用 `template publish --agent <id> --registry local --message "更新指令"`。

版本历史中的“切换版本”支持选择任意保留的非当前版本。回滚至 V1 后，可选中 V2 并确认切换，恢复 V2；切换不创建新版本，也不删除历史。

保存模板指令会在原 UUID 下创建新版本；回滚后保存仍递增版本号，旧快照保持不变。模板库使用页内详情，切换成功即更新当前模板，不打开详情弹窗，也不等待版本列表刷新。批量发布会先删除冲突路径再创建新文件，支持文件与目录相互替换。

工作区目录与文件缓存按模板身份、生效版本及更新时间隔离。切换版本时丢弃旧预览及尚未完成的旧目录请求，再加载所选版本的指令、技能和 MCP 配置。
