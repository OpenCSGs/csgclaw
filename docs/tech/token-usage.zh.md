# 本轮 token 消耗

[English](token-usage.md) | 中文

对话和线程回复结束后，在回复底部显示本轮 token 消耗和本轮选择的模型。
选择 `auto` 时隐藏模型名称，即使网关返回了实际路由的模型也不展示。
悬浮或聚焦 token 数可以查看输入、输出，以及可用的缓存输入和推理输出明细。
操作栏空间不足时，用量收起为信息图标；悬浮或键盘聚焦图标仍可查看总量、模型及明细。

一轮包含该智能体为完成回复而执行的多次模型调用，包括工具调用前后的模型请求。
每次输入包含实际发送的系统提示词、历史、工具定义和工具结果，因此多次发送历史会重复计入输入。
输出可能包含推理和工具调用参数，不能用页面可见文本长度推算。
缓存输入和推理输出属于明细，不再额外加到合计。这里显示 token 数，不换算费用。

## 统计与保存

- Codex 由 HTTP LLM Bridge 在协议转换前采集每次成功响应的原始 usage，
  包含流式响应的最终计数；每次 HTTP 请求仅报告一次，统一 Chat Completions、Responses 和 Messages 格式，
  按精确的智能体、会话和轮次 ID 汇总。原生线程累计计数仅用于上下文显示，不再用于计算回复消耗，
  冷恢复时历史计数不会计入新一轮。
  其他调用缺失或返回无效 usage 时标记为部分统计；认证或协议拒绝后的重试不计为缺失。
  上下文恢复延续保留已收集的用量，下一轮重新开始，后台记忆会话不计入用户回复。
  未经过 bridge 观察或缺少原生轮次标识的请求显示用量不可用，不再用历史累计值推算。
- DSH 转发已提交的 `assistant/message.usage` 和 `compaction/summary.usage`，按事件序号去重，在当前会话轮次内汇总。
  自动压缩调用模型生成摘要的消耗也计入本轮。
  缺少用量或输出被中断时标为部分统计。不会把上下文占用的 `usage_update.used` 当作本轮消耗。
- 用量通过 `token_usage` 活动事件传递，连同模型快照保存在消息的
  `metadata.csgclaw.turn_progress.usage`，刷新和重启后仍可读取。
  未知用量与真实零值分开处理；失败、取消和重启中断的回复保留已有用量，并标记部分统计。
  旧消息没有用量数据时不补造历史统计。

## OpenCSG 实际调用结果

2026-10-19 使用当前配置的网关凭据进行了最小请求，确认以下格式。数值来自不同调用，仅作格式示例。

| 接口 | 实际返回的输入 | 输出 | 合计 | 说明 |
| --- | ---: | ---: | ---: | --- |
| Chat Completions 流式，`auto` | 14 | 144 | 158 | `prompt_tokens` / `completion_tokens` / `total_tokens` |
| Responses 流式，`auto` | 50 | 139 | 189 | `input_tokens` / `output_tokens` / `total_tokens` |
| Messages 流式，`auto` | 14 | 164 | 178 | 输入在后面的 `message_delta` 才更新 |

还验证了 Chat 和 Responses 非流式响应，以及指定 `qwen3.7-plus` 的 Chat 流式响应。
`auto` 的 Chat 响应模型为 `qwen3.7-plus`，但前端仍隐藏名称。
Chat 的流式用量可能晚于 `finish_reason`，因此需读取后续独立用量块；请求显式开启 `include_usage`。
Responses 的 `x_details` 是重复的计费明细，不再次累计。
详细脱敏 JSON 示例见[英文技术说明](token-usage.md)。

当时配置的本机 CSGHub Lite 服务无法连接；没有配置凭据的其他厂商未逐一调用。
兼容性通过三种协议的转换回归测试验证，不代表已实测每个厂商。

## 验证入口

后端协议测试覆盖三种接口、流式与非流式调用、Chat 与 Responses 消费端及延迟用量块；
原生 Codex 进程测试验证协议切换后仍能收到正确用量。
还运行了仓库指定的 DSH `0.1.5-rc.3` 原生测试及冷恢复测试：上下文估算占用约 12.5K，
本轮输入 1000、输出 20，最终消耗值为 1020，两个指标保持独立。
自动压缩轮发生两次模型调用时，已验证合计为 2040，回复和摘要各计入一次。
Codex 原生 HTTP 测试覆盖完整用量、首次或末次调用缺失、全部缺失，下一轮恢复完整统计，以及上一轮消耗 110 token 后冷恢复、首个或全部请求缺失 usage 的场景。
运行时与消息测试覆盖多次调用、重复和过期事件、跨轮隔离、部分统计及历史持久化。
前端测试覆盖格式化、未知与零值、`auto` 隐藏名称；UI Lab 提供普通、auto 和长模型名称的预览。
